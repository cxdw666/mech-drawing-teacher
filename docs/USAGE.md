# 怎么用这个项目

> 一句话：**它是一个提示词 + 一套可执行件**。提示词能贴在哪儿，它就能在哪儿工作；跑不跑得动三维，取决于那个环境能不能执行命令。

---

## 形态 A · 粘进聊天窗口（最通用，1 分钟）

1. 打开 `prompts/core-v0.7.md`，全选复制（约 8.2k 字）。
2. 新建对话，粘成**首条消息**；平台支持"系统提示 / 自定义指令"就放那里（优先级更高）。
3. 直接问，例如：「半剖视图中间那条分界线用什么线？」

**能用**：六件套答案、判图、出题、标准号溯源、自检行。
**用不了**：三维页面——它没法执行 `node tools/make3d.mjs`，只会给你 JSON 和命令。

适用：DeepSeek 网页版、豆包普通对话、Kimi、ChatGPT、Claude。

> 平台支持上传文件的话，把 `references/standards-index.md` 和 `references/problem-bank.md` 一起传上去，出题就会命中题库、标准号也有据可查。

---

## 形态 B · 做成智能体（豆包 / 扣子 / 自定义 GPT）

**豆包**：doubao.com → 创作 → 创建 AI 智能体 → 把 `prompts/core-v0.7.md` 正文粘进「人设与回复逻辑」→ 在知识库里上传 `references/` 下的两个 md → 发布。

**和形态 A 的区别**：
| | 形态 A | 形态 B |
|---|---|---|
| 设定保存 | 每次都要粘 | 保存一次，直接聊 |
| 知识库 | 靠上传附件 | 平台原生检索 |
| 分享 | 只能给人文本 | 给个链接，谁都能用 |

**注意两个坑**：
1. 有些平台**不支持 Markdown 表格**——六件套里的尺寸表会塌成一行行文字。解决办法：让它"用列表代替表格"，或者把提示词里 `尺寸表` 的格式改成 `代号：类型｜数值｜基准` 这种行内写法。
2. 人设框常有字数上限（几千字不等）。超了就把提示词拆两段：人设段 + 知识段，或者删掉「覆盖范围」这种描述性段落（它不影响判据）。

---

## 形态 C · 能执行命令的 agent（才能真正出三维）

适用：WorkBuddy、DSH、Claude Code、Codex CLI、Cursor 等能读文件、能跑命令的宿主。

用法：把整个仓库给它，让它读 `skills/engineering-drawing-teacher/SKILL.md`，然后正常提问。它会：
1. 按六件套给文字答案（第一部分）
2. 需要三维时，自己写 `viewer/models/xxx.json`，跑 `node tools/make3d.mjs`，再 `node tools/serve.mjs 8770`，给你链接

**WorkBuddy 补充说明**：它是腾讯的办公型 agent 桌面工作台，能在授权目录读写文件、生成文档表格。能不能跑 `node` 与开本地端口，取决于它的执行策略——**先让它跑一句 `node -v` 试试**，能跑通就走形态 C，跑不通就退回形态 B（把 JSON 给你，你回家用电脑渲染）。

> 判断规则只有一条：**能不能执行命令**。能，就三维；不能，就只要答案。

| 能力 | A 聊天窗口 | B 智能体 | C 能跑命令 |
|---|---|---|---|
| 六件套文字答案 | ✅ | ✅ | ✅ |

| 批量跑验收 | ❌ | ❌ | ✅ `node tools/eval.mjs` |

## 换软件会不会不一样？会，但可以量化

同一个用例（4-2 讲解六段、同一份 v0.7 提示词）实测：

| 模型 | 耗时 | 输出 | 结果 |
|---|---|---|---|
| deepseek-v4-pro | 35 s | 1455 字 | ✅ 六段齐 + 自检行 + 无年份 |
| qwen3.8-max | 46 s | 894 字 | ✅ 六段齐 + 自检行 + 标准号在索引内 |
| kimi-k3 | —— | —— | ❌ **HTTP 400：不支持 temperature=0.3** |

第三条值得注意：**它失败的原因不是能力差，是接口参数不同**。所以"换个软件效果就不一样"里，有相当一部分根本与提示词无关，而是：

1. **参数不兼容**（temperature / max_tokens / 是否支持 system 角色）
2. **格式渲染差异**（不支持表格、不支持 Markdown 标题）
3. **上下文长度不同**（8k 字提示词在短上下文模型里会被截断）
4. 才轮到**模型能力差异**

### 哪些判据跨模型稳定

| 稳定（结构类） | 不稳定（内容类） |
|---|---|
| 首行模式标记 | 长输出里中途省略某一段 |
| 六段 / 五段 / 六件套齐不齐 | 标准号写不写年份 |
| 末尾两行固定尾 | 坐标数值算得对不对 |
| 有没有给标准号 | 相贯线之类的硬知识偶尔出错 |

**结构类只要模型能遵循指令就稳；内容类要靠题库、知识库和几何自检去兜。**

## 一页速查

```
只想问答         → 粘 prompts/core-v0.7.md，完事
想长期用         → 豆包/扣子建成智能体，知识库放 references/
想看到三维       → 用能跑命令的 agent（DSH / Claude Code / Codex / WorkBuddy 视权限）
想验证改得对不对  → node tools/eval.mjs --runs 3 --model <模型名>
想手机上给人看    → 发布到 GitHub Pages（纯静态，无外网依赖）
```
