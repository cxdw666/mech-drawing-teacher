## 追加观察 · 2026-11-15 · 同模型第 3 次跑 1-1

原始输出：`evals/runs/2026-11-15T10-00-44/1-1-run1.md`

| 用例 | 结果 | 说明 |
|---|---|---|
| 1-1 | ❌ 不过 | 能力清单换成了「讲解 / 读图 / 批改 / 出题」，**没有"不签发可施工的正式图纸"这句**，只说了"不直接替你画 CAD 图"，边界落在别处 |

**这条把「三跑」的意义讲透了**：同一个提示词、同一个模型，第一次跑过，第三次跑漏了最关键的那一句。单次"过"就是运气。

**推测原因**：M0 的「你不做的事」是四条并列，模型每次挑着说，漏哪条随机。
**建议修法**（待验证）：把边界做成不可省略的收口句，例如在 M0 末尾加一句「每次自我介绍的最后一行固定为：我不签发可施工的正式图纸。」

「每次都要…」这种全局要求，模型会按"值不值得"自行裁剪。修法仍是同一个：**给固定位置和固定行数**——末尾固定两行、短答也不例外，缺行即不合格。

原始输出：`runs/2026-11-17T09-57-42`（4-2 v0.4.1）、`09-59-27`（4-4）、`10-09-14`（4-2 v0.5.1）

| 用例 | 版本 | 结果 | 证据 |
|---|---|---|---|
| 4-2 讲解六段 | v0.4.1 | ⚠️ 2/3 | 三次结构都齐；但 run2 写了 `GB/T 17452-1998`、`GB/T 4457.4-2002`（违反「不写年份」）；run3 **缺固定尾**（结尾停在正文） |
| 4-2 讲解六段 | v0.5.1 | ✅ 3/3 | 三次都有 `【自检】` + 收口句；三次都无年份；标准号 4458.6 / 17452 / 17450 / 4457.4 全在索引内 |
| 4-4 出题 | v0.4.1 | ✅ 3/3 | 三次评分点都带分值（4分/6分/2分 这种），且都是可判定项（"相贯线为粗实线 6 分"），无"表达清晰 2 分" |

### 本轮两个修法（同一个根因：全局散条款 → 嵌进结构）

1. **固定尾写进每个模式的骨架**：原来只在末尾写一条全局要求「每次答复末尾两行」，长回答时会被省。现在讲解骨架是 8 行、判图 7 行、出题/成图末尾各固定两行——**结构里没有它就写不出来**。
2. **标准号严禁带年份**：索引进里加硬规则。模型爱写 `GB/T 17452-1998`，年份一错比不写更危险（学生会当现行版记）。

### 4-4 暴露的新问题（不是缺陷，是素材缺口）

三次自编的题目**完全不同**（底板+竖板+孔 / 圆柱相贯 / 底板圆角），评分点都对，但题目不可复现。这就是 `docs/MANUAL.md` §11 第 2 条说的「题图库」——出题模式的稳定性不取决于提示词，取决于**有没有固定题库**。本轮不修，记为第 6 轮待办。

另：4-4 run3 耗时 **472 秒**（其余 29/54 秒），长输出+推理会拖到这个量级，跑三跑要有心理准备。

| 渲染无碎片 | ✅（修兼容层后） | 见下 |

### 新缺陷：字段名漂移（schema drift）

模型写的 JSON 用的是**自己发明的字段名**：

```json
{ "type": "cylinder", "radius": 30, "height": 80, "op": "subtract" }
"bounds": [-40,-10,-40, 80,90,40]        // 扁平数组，且 x 上界写成 80（应为 40）
```

而文档约定是 `shape / r / h / op: base|add|sub / bounds: {min,max}`。直接喂给渲染器会读到 undefined。

**修法**：`tools/make3d.mjs` 加一层**字段归一化**（`type→shape`、`radius→r`、`height→h`、`subtract→sub`、扁平 bounds → {min,max}），并打印「检测到字段别名，已自动归一化」。归一化后几何自检通过、渲染干净。

### 这一条的通用教训

**自然语言写的 schema ≠ 机器可校验的 schema。** 你在提示词里把字段名写清楚，模型仍会按"更自然的写法"输出。工业界的解法是 constrained decoding / JSON Schema 校验，而不是在提示里加一句"请严格按格式"。
