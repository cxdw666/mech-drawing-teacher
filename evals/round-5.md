# 第 5 轮验收 · 三维自动出图

**这一轮测的不是"能不能画图"，是"模型自己写的几何描述能不能直接渲染"**。

提示词：`prompts/core-v0.6.md`（v0.6 起含「方向对照表 + 三条防崩规则 + 口头核算」）

---

## 5-1 · 自动出三维（同一道题，看它一次能不能写对）

**输入**
```
帮我看看这个零件：圆柱 φ60 高 80，中间同轴通孔 φ30，侧面开径向孔 φ12。画三视图，并给我能旋转看的三维模型。
```

**通过判据（5 项全中）**
- [ ] 六件套齐全（①立体形成过程 … ⑥图例）
- [ ] 【三维查看】三行齐：JSON 文件 / 生成命令 / 「体素近似、不按比例」声明
- [ ] **rotation 与描述一致**：说"正对主视方向"就必须是 `[90,0,0]`
- [ ] **切割体留余量**：径向孔长度 ≥ 66（不能正好 60），通孔长度 ≥ 84
- [ ] **写出数值核算句**：外廓 / bounds 外扩 / 超出量，三个数字都在

**渲染后判据（拿它写的 JSON 真跑）**
- [ ] `node tools/make3d.mjs` 无「端面共面」告警
- [ ] 打开页面：通孔是干净的圆孔，径向孔是一个完整圆孔，**没有碎片**

## 记录表

| 用例 | 版本 | 结果 | 失败点 |
|---|---|---|---|
| 5-1 | v0.5.1 | ⚠️ 结构对、几何错 | rotation `[0,0,90]` 与"正对主视方向"矛盾；径向孔长 60 = 外径 → 共面碎面 |
| 5-1 | v0.6.0 | ✅ 5 项结构全过 + 渲染干净 | 唯一新增问题：字段名漂移（type/radius/height/op:subtract、扁平 bounds），已由 make3d 归一化层吸收 |

**通过线**：结构 5 项 + 渲染 2 项全过，且三跑里至少两跑渲染干净（几何错误是概率性的，模型每次算的位置可能不同）。
