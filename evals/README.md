# 验收怎么跑

本项目的验收是**人工协议**，不需要 API key：任何聊天模型都能跑，结论记成一行表。

## 协议

1. 开一个**干净对话**（不要带历史消息，历史会污染判据）。
2. 把 `prompts/` 下当前轮次的提示词全文粘贴为系统提示；平台不支持系统提示时，作为第一条消息发送，并在末尾加一行「以上为你的设定，回复『已就位』，不要复述」。
3. 逐条发送该轮 `evals/round-N.md` 里的**输入**。
4. 对照**通过判据**逐项打勾，任何一项不中就记不通过，写清失败点。
5. 结果填进 `evals/results.md` 的记录表，注明模型名与日期。

## 规矩

- 判据是二值的，不写「基本符合」「大致对」。
- 只测当前轮次；后续轮次的用例对早期版本必然不过，那是设计如此，不是 bug。
- 换模型要重跑：不同模型对「不许画」这类否定约束的服从度差异很大，A 模型过 B 模型不过很常见。
- 同一模型同一用例，稳定与否看三次：三次都对才算过（否定约束最容易偶发失效）。

## 为什么不用脚本

提示词工程的主要失效是**行为漂移**，不是字符串匹配。自动判「有没有出现标准号」很容易，判「有没有假装画对」需要人眼看输出形态。等第 4 轮装完 M7 自检钩子，再考虑给可机判的那部分（标准号是否在索引内）加脚本。
