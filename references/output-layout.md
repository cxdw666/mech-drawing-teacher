# 成图版式规范 v1（从一张样板图反推）

> 样板：`7-24(3) 带切口立体的侧面投影（左视图）—— 作图过程`。
> 这张图值得学的不是它的答案，是它的**信息顺序**。以下每条都是可判定的，不是"排版好看"这种主观要求。

## 一、整套输出固定六件套，顺序不变

| # | 件 | 样板里长什么样 | 不写会怎样 |
|---|---|---|---|
| ① | **立体形成过程**（分步） | 三个轴测图 + ①②③ 文字：原形是什么 → 切掉什么（距轴线多少、多高、是否贯通）→ 切完后**主视图上出现什么特征** | 学生知道答案但不知道形体怎么来的，换一题就不会 |
| ② | **观察方向声明** | "左前上方，同时看到顶面(+Z)、前面(−Y)、左面(−X)"；并说明这个方向与"从左向右看得到左视图"一致 | 三视图朝向搞错，是作图类最基础的翻车点 |
| ③ | **三视图逐视图的图元** | 主视图 / 左视图 / 俯视图，各自的可视线（粗实线）、不可见线（虚线）、轴线（点画线）分别是什么 | 只给"外形是个凸字形"，学生无法照着画 |
| ④ | **三向对位校验** | 图上的辅助线：主↔俯 竖虚线（长对正）、主↔左 水平虚线（高平齐）、俯↔左 经 45° 斜线（宽相等） | 这是"视图对不对"的唯一证据。只写"符合投影关系"等于没校验 |
| ⑤ | **尺寸表** | 118 总高、80 上部宽、88 底部宽、φ100、48 凸台宽 | 尺寸漏一个，图就没法画 |
| ⑥ | **图例** | 可见轮廓=粗实线 / 不可见轮廓=虚线 / 轴线=点画线 / 辅助投影线=浅色 | 线型约定不声明，读者不知道你在用哪套约定 |

## 二、版式铁则（可判定）

1. **三视图位置固定第一角画法**：主视图在左上，俯视图在**主视图正下方**，左视图在**主视图正右方**。不许把俯视图画到上面（那是第三角）。
2. **对位必须显式**：至少给出 3 组对位，每组写"谁↔谁、对齐项数或数值"。样板用辅助线表达，我们用文字表达同一件事。
3. **45° 斜线必须交代**：宽相等不是"看一眼相等"，是由俯视图的 Y 向尺寸经 45° 斜线转到左视图。文字版要写「俯视图 Y=a → 45° 线 → 左视图 Y=a」这样的转换，而不是直接说"宽相等成立"。
4. **每切一刀，都要说清"哪个视图上多了/少了哪条线"**：这是样板里 ①②③ 下方那三行小字的全部价值。
5. **图例不可省**，且必须和正文用词一致（正文写"细点画线"，图例就不能写"中心线"）。
6. **不确定的尺寸标 `[假设]` 并在末尾集中复述**；假设 ≥4 项时开头先声明。

## 四、什么时候升级成 SVG

文字版解决"结构一致"，解决不了"看着像图"。需要真图时用 `assets/three-view-template.svg` 当骨架：视图框、三组辅助线、45° 斜线、图例都已就位，只需往里填 `<path>`。

模型生成 SVG 时只允许改 `<g id="content-*">` 里的内容，不许动布局骨架——**布局一改，三视图就不再对位了**，而这正是这张图要教的东西。
